# Windows 使用指南

DoIP 诊断控制台 · Windows 部署与日常使用（面向使用者的完整步骤）

---

## 一、环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11（64 位） |
| Node.js | **20 或更高版本**（LTS 即可，推荐 22.x） |
| 浏览器 | Edge / Chrome（系统自带 Edge 即可） |
| 网络 | 连接真实 ECU 时需与目标车辆同一网段；连内置仿真则无需外网 |

**不需要**安装 Python、Git 或任何驱动；工具是纯 Node 进程 + 浏览器页面。

### 1. 安装 Node.js

1. 打开 <https://nodejs.org/>，下载 **LTS 版本**（Windows Installer，.msi）
2. 一路下一步安装（全部默认即可，安装器会自动配置 PATH）
3. **安装完成后，关闭并重新打开**命令行窗口（旧的窗口不会刷新 PATH），执行：

```bat
node -v
```

显示 `v20.x.x` 或更高即成功。若提示"node 不是内部或外部命令"，见文末【常见问题】。

---

## 二、启动（推荐：一键脚本）

在项目文件夹里，**双击 `scripts\start.bat`**，或在命令行执行：

```bat
scripts\start.bat
```

脚本会自动完成三步：安装依赖（仅首次，约 1-2 分钟）→ 构建前端 → 启动后端，并在约 3 秒后**自动打开浏览器**。

> 已构建过、只想快速启动时，可跳过构建：
> ```bat
> scripts\start.bat --no-build
> ```

启动成功的标志——终端会打印：

```
后端已启动：http://127.0.0.1:8787  （WS: ws://127.0.0.1:8787）
界面地址：http://127.0.0.1:8787
```

**保持这个黑窗口开着**（它就是后端进程），用完关闭窗口或按 `Ctrl-C` 退出。

### 端口被占用怎么办

8787 被别的程序占用时，工具会自动顺延到 8788-8797。**以终端打印的实际地址为准**，浏览器若打开的是旧端口，手动改成终端里那个即可。

---

## 三、启动（手动方式）

不想用脚本时，等价的三条命令：

```bat
npm install
npm run build
npm start
```

（`npm start` = 构建 + 启动，所以装完依赖后直接 `npm start` 也行。）

---

## 四、日常使用

1. **连内置仿真 ECU**（无需任何硬件）：界面左上模式选「仿真 ECU」→ 点「连接」。若仿真未启动，工具会自动拉起，正常情况只点一次即可。
2. **连真实 ECU / 网关**：模式选「真实 ECU」→ 填目标 IP 和端口（DoIP 标准 13400）→ 点「车辆发现」可先扫描确认在线 → 点「连接」。
3. 诊断报文、Trace 查看、导出（CSV/JSON/HEX）等操作见界面各区，或查阅 `README.md`。

### 数据都存在哪

| 内容 | 位置 |
| --- | --- |
| 报文落盘（trace-logs） | `C:\Users\你的用户名\.doip-console\trace-logs\` |
| 运行日志 | `C:\Users\你的用户名\.doip-console\logs\` |

在界面底部状态栏点「日志」/「录盘」旁的打开目录按钮，可直接在资源管理器中打开对应文件夹。

## 五、命令行工具（可选）

不想开浏览器时，可以直接用命令行发诊断请求（复用同一套协议栈）：

```bat
npm run cli -- scan --port 13401          :: 车辆发现
npm run cli -- send 22F190 -p 13401       :: 读 VIN
npm run cli -- alive -p 13401             :: 存活检查
npm run cli -- entity-status -p 13401     :: 实体状态
npm run cli -- power-mode -p 13401        :: 电源模式
```

> npm 传参的 `--` 分隔符不能省略。

想直接敲 `doip` 命令：

```bat
npm link
doip send 22 F1 90 -p 13401 --json
```

- 连内置仿真：端口用 `13401`（先 `npm run sim:up`，或在界面点「启动仿真 ECU」）
- 连真实 ECU：端口用默认 `13400`，加 `-H <ECU的IP>`
- `--json` 输出机器可读结果，适合批处理脚本
- 危险操作（`0x11` 复位等）需加 `--yes`

完整命令、选项与退出码见 [CLI 文档](./CLI.md)。

## 六、Windows 防火墙提示

- 工具本身只监听本机（127.0.0.1），**不会触发防火墙弹窗**。
- 首次**连真实 ECU** 发起「车辆发现」时，Windows 可能为 Node.js 弹出防火墙确认——勾选允许即可（这是 UDP 广播请求需要出站权限）。
- 若车辆发现一直扫不到：检查网卡是否选对（多网卡笔记本常见）、网段是否与车辆一致；工具会自动降级为单播探测，最坏情况是发现列表不全，不影响手动填 IP 直连。

## 七、常见问题

| 现象 | 原因与解法 |
| --- | --- |
| `node 不是内部或外部命令` | Node 没装或 PATH 未刷新。确认 nodejs.org 的安装器跑完；**重开命令行窗口**再试 |
| `npm install` 很慢或超时 | 网络问题。可换国内镜像：`npm config set registry https://registry.npmmirror.com` 后重跑 |
| 双击 start.bat 一闪而过 | Node 未安装。在 cmd 里手动跑 `scripts\start.bat` 看具体报错（脚本里已加 pause，双击失败也会停住显示原因） |
| 端口提示被占用 | 工具自动顺延端口，用终端打印的实际地址访问即可；或关掉占用的程序后重启工具 |
| Excel 打开导出的 CSV 中文乱码 | 不会发生——导出自带 UTF-8 BOM。若用了别的方式导出才可能乱码 |
| 界面打不开但终端正常 | 看终端实际端口（可能顺延到 8788+），手动在浏览器输入终端里的地址 |

## 八、开发模式（可选）

改前端代码需要热更新时，开**两个**命令行窗口分别运行：

```bat
node --import tsx server\src\index.ts    :: 窗口1：后端（8787）
npm run dev                              :: 窗口2：Vite 开发（5273，已代理 /api 与 /ws）
```

界面地址变为 <http://127.0.0.1:5273>。日常使用不需要开发模式。
